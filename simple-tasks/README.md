# Simple Tasks

## Introduction
현대인들은 복잡한 일정들과 상황 가운데 있다.
이것은 당장 해야할 일들을 하지 못하게 하는 결과를 초래한다.
사람이 실행하지 못하는 것은 정보의 부족이 아니라 많은 정보로 인한 실행 결정을 유예하기 때문이다.
복잡한 일정들과 상황을 파악하고 유연하게 당장 해야 할 일을 추론하기 위해서는 '지능'이 필요하다.

이 '지능'은 처음에는 간단한 실행 목표를 제공하여,
사용자가 업무에 진입하게 하고, 업무를 진행하면서 떠오르는 생각들을 정리하게 도와준다.
이를 바탕으로 결과적으로 구체적이고 창의적으로 업무를 수행하게 도와준다.

Simple Tasks는 이 '지능'을 인공지능으로 대치하여 단순하게 일정을 처리할 수 있도록 도와주는 솔루션이다.

## Target
목표 타겟은 
1. "업무 시작 준비 단계의 회사원", 
2. "회의 혹은 짧은 쉬는 시간을 마친 회사원"
3. "식사 후의 회사원"
Skill로만 프로덕트를 만들기에
다양성을 제거해서 생각한 목표이다.

## Goal
- 사용자가 어떠한 상태에 있든 바로 일정을 실행가능하게 하기
- 추론된 일정 외에 다른 많은 것들을 생각하지 않아도 되게 하기

## 사용자가 보는 것

"지금 뭐해야 해?" 한 문장이면 카드 한 장이 나온다. 목록도, 조언도, 되묻는 질문도 없다.

```
미처리 12 · 오늘 마감 2

- 지금 → 3분기 보고서 초안
- 이유 → 오늘 18시 마감, 4개가 이거 대기 중
- 시작 → 문서 열고 목차 3줄
- 종료 → 목차 3줄이 문서에 있으면
```

아래에 `완료` / `너무 큼` / `다른 거` / `오늘 그만` 버튼이 붙는다. 사용자는 쓰지 않고 누르기만 한다.
`완료`를 누른 그 순간에만 두 칸을 자유 입력으로 받는다 — "다음에 이어서", "하다가 떠오른 거".
방금 실행한 직후라 이 글쓰기는 결정이 아니라 회상이고, 그래서 비용이 거의 없다.
이 수확이 다음 카드의 재료가 되므로 별도의 할 일 등록 절차가 필요 없다.

## 설치와 발동

스킬 폴더를 런타임의 스킬 경로에 넣는다. 그 다음은 런타임이 스킬을 **자동으로 탐색하는지**에 따라 갈린다.

**A. AI지침(사용자 지침)을 설정할 수 있는 환경** — 아래 한 줄을 등록하면 자동 발동한다.

```
사용자가 "지금 뭐해야 해?", "뭐부터 하지?", "이제 뭐하지?", "할 일 뭐 있어?"처럼 무엇을
할지 묻거나 "~해야 하는데"처럼 할 일을 선언하면, 직접 답하지 말고 먼저 simple-tasks
스킬을 찾아 읽고 그 지침대로 응답한다.
```

**B. 지침을 설정할 수 없는 환경** — 스킬 이름을 붙여 부른다. 이것이 기본 사용법이다.

```
simple-tasks 지금 뭐해야 해?
```

호출 방식이 달라질 뿐 그 뒤의 동작은 같다. 이 스킬이 없애려는 비용은 "무엇을 할지 고르는
결정"이지 스킬 이름을 치는 열 글자가 아니므로, 명시 호출은 설계를 훼손하지 않는다.

**동작 판정 기준** — 아래 셋을 모두 만족해야 스킬이 실제로 적용된 것이다.

1. 첫 줄이 `미처리 N · 오늘 마감 N`
2. `- **지금** →`으로 시작하는 네 줄
3. 그 뒤에 선택지 버튼

서두가 한 줄이라도 붙거나 할 일 목록이 나열되면 스킬이 적용되지 않은 것이다.

## 구성

| 파일 | 역할 | 로드 시점 |
|---|---|---|
| `SKILL.md` | 절대 규칙, 카드 명세, 분기 라우팅 | 매 턴 |
| `references/responses.md` | 완료·수확, 너무 큼, 다른 거, 이탈 회수 | 버튼을 누른 뒤 |
| `references/modes.md` | 콜드 스타트, 시간대별 성격, 하루 닫기 | 목록이 비었거나 시간대 판정이 필요할 때 |
| `references/commands.md` | 커맨드·토큰 규약 | 인자를 확인할 때 |
| `references/design-notes.md` | 설계 근거 | 런타임에 읽지 않음 |
| `scripts/` | 상태·우선순위·크기 보정·토큰 | 스킬이 호출 |

매 턴 로드되는 양을 8.6KB로 제한하고 나머지는 해당 분기에 들어갔을 때만 읽는다.
규칙이 희석되면 모델이 "도움이 되려는" 기본 성향으로 되돌아가 목록과 조언을 내놓기 때문이다.

## 규칙을 코드로 강제한 부분

문서로만 있는 규칙은 지켜지지 않는다. 셋은 스크립트가 구조적으로 막는다.

- **목록 비공개** — 상태 파일의 항목 텍스트를 base64로 인코딩한다. 파일을 열어도 읽히지 않는다.
- **명시적 완료** — `pick`이 일회용 토큰을 발급하고 `complete`가 그것을 검증한다. `pick`을 거치지 않은 완료는 기록될 수 없다.
- **크기 보정** — 거부 로그 최근 10건을 스크립트가 집계해 카드 크기를 자동으로 낮춘다.

## Thinking
- 일정들과 상황에 대한 입력은 어떻게 받을 것인가? - 오로지 챗봇의 입력으로만
- 언제 받을 것인가? - 실행 완료 직후에
- 아무런 데이터 없는 최초 1회 질문은 상태 메모를 바탕으로 그리고 현재 상황(시간)을 보고 간단한 실행 목표를 준다. (예시: 커피 마시면서 프로젝트 생각하기 등)
- 첫 카드는 맞을 필요가 없다. 완료 가능하기만 하면 되지만 사용자가 좀 더 업무를 생각해 볼 수 있을 만한 행위로 추천하는 것이 좋다.
- 추천 알고리즘 우선순위: `완료 가능성 — 반드시 끝낼 수 있는가`,`생각 유발 — 하면서 업무에 대한 생각이 떠오를 만한가`,`정확도-사용자가 실행하고자 하는가`
- 사용자 완료 여부는 사용자가 명시적으로 완료체크할 때만 완료했다고 가정한다.
