# 맥락과 콜드 스타트

`load`와 `pick`이 돌려주는 `mode`를 그대로 쓴다. **모드 판정을 사용자에게 말하지 않는다.** 결과만 카드에 반영한다.

## 시간대별 카드 성격

`mode.mode` 값에 따라 `시작` 줄의 기본 크기와 첫 카드의 성격이 달라진다. 판정 없이 만들면 오후 5시에 아침용 문구가 나간다.

| `mode.mode` | 상황 | 기본 크기 | 첫 카드 성격 |
|---|---|---|---|
| `morning` (~11시) | 업무 시작 준비 | 중간 | 하루의 방향이 잡히는 행위. 어제 문서 열기 |
| `midday` (11~13시) | 오전 마무리·회의 직후 | 중간 | 재진입 메모를 먼저 읽고 끊긴 지점으로 복귀 |
| `after_lunch` (13~14시) | 식사 후 | 최소 | 몸을 다시 책상에 붙이는 행위 |
| `afternoon` (14~16시) | 오후 실행 | 중간 | 마감이 오늘인 것 |
| `closing` (16시~) | 하루 닫기 | 작게 | 아래 참조 |

회의나 짧은 휴식 직후라는 신호가 대화에 있으면 시각과 무관하게 크기를 한 단계 낮추고 재진입 메모가 있는 항목을 우선한다.

`calibration.shrunk`가 true면 위 기본 크기에서 한 단계 더 내린다. 거부 로그가 "지금 내는 카드가 너무 크다"고 말하고 있다는 뜻이다.

## 하루 닫기 세션

`mode.is_closing`이 true일 때. 늦은 오후에 열린 세션은 새 일을 시작시키는 자리가 아니라 **내일 아침 첫 카드의 재료를 만드는 자리**다. 이 시간대에 큰 일을 지목하면 사용자는 시작도 못 하고 카드만 닫는다.

- **지금** → 하루 닫기
- **이유** → 5시 23분, 지금 적어두면 내일 아침에 안 헤맴
- **시작** → 지금 열린 창이나 파일 하나 열기
- **종료** → 그 창을 닫으면

**선택지에서 `너무 큼`을 뺀다.** 이미 최소 크기다. `완료` / `다른 거` / `오늘 그만` 셋만 낸다.

완료 수확의 첫 칸이 그대로 내일의 재진입 메모가 되므로, 이 세션의 수확은 다른 세션보다 값이 크다.

## 콜드 스타트

`open_count`가 0이거나 `pick`이 `no_candidates`를 돌려줄 때.

**사용자에게 목록을 쏟아내라고 요구하지 않는다.** 그것은 작성 요구고, 이 스킬이 없애려는 바로 그 비용이다.

다만 **상태 파일이 비었다는 것과 아무 정보가 없다는 것은 다르다.** 사용자는 목적을 가지고 들어왔고, 그 목적은 트리거 발화에 이미 붙어 있다. 비싼 것은 타이핑이 아니라 조사(survey)다. "오늘 할 일 알려줘"는 업무 전체를 훑게 만들지만, 방금 스스로 말한 것을 쓰는 데는 비용이 없다.

### 1. 발화에서 먼저 줍는다

카드를 만들기 전에 사용자가 방금 친 문장을 읽는다. 맨 "뭐하지"만 오는 경우는 드물다.

| 발화 | 주울 것 |
|---|---|
| "보고서 써야 하는데 뭐부터 하지" | 항목 `보고서` + 맥락 `보고서` |
| "아 회의 끝났는데 뭐하지" | 크기 한 단계 축소 + 항목 `회의에서 나온 것 정리` |
| "김팀장한테 답장해야 되는데" | 항목 `김팀장 회신` + 맥락 `김팀장` |
| "뭐부터 하지" | 없음 → 2로 간다 |

**맥락은 발화에 실제로 나온 파일·사람·도구 이름만 줍는다.** 없으면 비워 둔다. 지어내면 다음 카드가 엉뚱하게 딸려 온다([references/commands.md](commands.md)의 "항목 그래프").

주웠으면 등록과 카드 선택을 한 번에 받는다.

```bash
python scripts/simple_tasks.py add "보고서" --size S --context "보고서" --next --first
```

- **지금** → 보고서
- **이유** → 9시, 방금 이거 때문에 들어옴
- **시작** → 문서 열고 목차 3줄
- **종료** → 목차 3줄이 문서에 있으면

**되묻지 않는다. 확인도 받지 않는다.** "보고서 말씀이신가요?"는 질문만 있는 턴을 만들고 그 사이가 심의의 틈이다. 틀렸으면 `다른 거`가 3초 만에 받아낸다.

`이유` 줄이 사용자가 3초 안에 참·거짓을 판정할 수 있는 사실이 된다는 점이 중요하다. 시각만으로 만든 카드보다 언제나 낫다.

### 2. 발화가 비어 있으면 시각으로 낸다

시각만 보고 **완료 가능성 최우선으로 카드를 낸다.** 목록이 비어 있어도 카드는 나온다.

아침이면:

- **지금** → 하루 시작
- **이유** → 9시, 첫 30분이 오늘 흐름을 정함
- **시작** → 어제 마지막으로 열었던 파일 열기
- **종료** → 화면에 떠 있으면

시간대별 예시:

- 아침 첫 착석 → 커피 내려서 자리로 돌아오기 / 어제 문서 열어서 마지막 문단만 읽기
- 회의 직후 → 방금 회의에서 나온 것 한 줄 적기
- 식사 후 → 책상 정리 / 창 하나만 열기

**`이유` 줄에 "아직 아무것도 정해지지 않았다"류의 문장을 쓰지 않는다.** 사실이지만 사용자에게는 시스템이 아무것도 모른다는 고백으로 읽히고 카드의 신뢰를 깎는다. 시각이라는 사실 하나로 근거는 충분하다.

### 카드를 내기 전에 항목으로 등록한다

콜드 스타트 카드는 목록에 없는 항목이라 토큰이 없고, 토큰이 없으면 어떤 반응도 기록할 수 없다. **그래서 카드 문구를 정한 즉시 등록하고 토큰을 받은 뒤에 화면에 낸다.**

```bash
python scripts/simple_tasks.py add "하루 시작" --size S --next --first
```

`--next`가 등록과 카드 선택을 한 번에 처리하고 `card` 필드로 항목과 토큰을 돌려준다.

이렇게 하면 이후 `완료`·`다른 거`가 전부 일반 경로와 같아진다. 사용자가 그냥 나가더라도 `열린 카드`로 남아 다음 세션의 이탈 회수에 걸린다.

### 콜드 스타트에서의 반응 처리

**`너무 큼`을 선택지에서 뺀다.** 콜드 스타트 카드는 이미 최소 크기다. 하루 닫기와 같은 이유다. `완료` / `다른 거` / `오늘 그만` 셋만 낸다.

**`완료`** → 일반 수확과 같다. `complete "항목" --token TOKEN [--reentry ...] [--new-idea ...]`.
이 수확이 목록의 첫 항목이 된다. **콜드 스타트는 질문으로 푸는 게 아니라 첫 카드로 푼다.**

**`다른 거`** → 목록이 비어 있으므로 고를 다른 항목이 없다. `pick`을 다시 부르지 말고 **한 줄만 받는다. 여기가 목록을 채우는 자리다.**

```
방금 건 아니고, 그럼 지금 머리에 있는 거 하나만.
```

**"하나만"을 반드시 붙인다.** "뭐 있어?", "할 일 알려줘"는 목록을 훑게 만들어 조사가 되고, 조사는 이 스킬이 없애려는 심의 그 자체다. 반면 구체적인 제안이 방금 기각된 직후의 지목은 대조(contrast)라서 3초면 나온다. 빈 화면 앞에서 30분을 맴돌던 사용자가 틀린 카드 앞에서는 즉시 답한다. **오답도 촉매다는 심리 설명이 아니라 이 지점의 수집 전략이다.**

더 달라고 하지 않는다. 마감도 크기도 묻지 않는다. 아무렇게나 쓴 한 줄을 그대로 받고 형식은 뒤에서 붙인다.

```bash
python scripts/simple_tasks.py reject "이전 항목" --token TOKEN --reason "사유"
python scripts/simple_tasks.py add "받은 한 줄" --size S --next
```

여기서는 `reject`에 `--next`를 붙이지 않는다. 등록 전에는 고를 것이 없기 때문이다.

**사용자가 한 줄을 비워서 넘기면** 그때 같은 시간대의 다른 행위로 콜드 스타트 카드를 한 장 더 만든다. 위 예시 목록에 시간대마다 두어 개씩 있다. 사유를 기록하고 새 항목으로 등록하는 것은 같다.

**2회까지만.** 세 번째로 `다른 거`가 나오면 목록이 낡은 게 아니라 지금 일할 때가 아닌 것이므로 라운드 상한 처리로 넘어간다([references/responses.md](references/responses.md)).

**사용자가 아무것도 누르지 않고 나가면** 아무 처리도 하지 않는다. 카드는 열린 채로 남는 것이 정상이고, 미완료가 기본값이다.

수확이 비어서 두 번째 카드도 낼 게 없으면 같은 방식으로 완료 가능성 높은 카드를 한 번 더 낸다. 두세 세션이면 목록이 찬다. 조급해하지 않는다.

## 우선순위 원칙

항목 선택은 `pick`이 한다. 아래는 스크립트가 쓰는 기준이며, 콜드 스타트처럼 모델이 직접 카드를 만들 때의 판단 기준이기도 하다.

**첫 카드 — 진입이 목적.** 급한 일을 지목하는 것이 아니라 사용자를 움직이게 하고 다음 카드의 재료를 만드는 것이 목적이다.

1. **완료 가능성** — 반드시 끝낼 수 있는가. 최우선.
2. **생각 유발** — 하는 동안 업무에 대한 생각이 떠오를 만한가.
3. **정확도** — 실제로 하려던 일인가. 가장 낮은 가중치.

**`생각 유발`은 행위 선정 기준이지 카드 문구가 아니다.** 카드에 "~하면서 생각해보세요"라고 쓰지 않는다. 그건 조언이고 사용자를 다시 심의 모드로 밀어넣는다. 생각은 부수 효과로 두고, 완료 직후 수확 칸이 그것을 받는다.

**이후 카드 — 이미 움직이는 중.** 완료 가능성의 가중치를 낮춘다. 낮추지 않으면 마감이 임박한 큰 일이 영원히 밀리고 하루 종일 작은 일만 하게 된다. 순서는 재진입 메모 있는 항목 → 마감이 오늘 → 차단 중인 항목이 많은 것 → 크기가 작은 것.

동점이면 아무거나 고른다. 고민하지 말 것. 오답도 촉매다.
