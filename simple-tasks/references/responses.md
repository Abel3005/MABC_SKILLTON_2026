# 반응 처리

사용자가 버튼을 누른 뒤의 처리. **버튼을 누르는 즉시 스크립트로 기록한다.** 세션 종료 시점이 아니다. 세션이 격리되어 있으므로 방금 거부한 항목이 기록되지 않으면 다음 세션에서 똑같은 카드가 나오고 신뢰가 한 번에 무너진다.

`complete`와 `reject`에는 직전 카드의 `token`이 필요하다. 일회용이라 한 번 쓰면 소멸한다.

**`--next`를 붙여 기록과 다음 카드를 한 번에 처리한다.** 응답의 `card` 필드에 다음 항목과 새 토큰이 들어 있다. `pick`을 따로 부르면 왕복이 두 배가 되고, 카드가 뜨는 속도가 이 스킬의 체감 품질이다.

## 이탈 회수

`load`의 `has_open_card`가 true일 때. 직전 세션이 카드를 연 채로 끝났다는 뜻이다. **이것이 세션의 첫 출력이다.** 카드보다 먼저 낸다.

```
아까 "발주서 확인" 열어뒀는데 어떻게 됐어?
```

선택지 도구로 `완료` / `하다 말았음` / `손도 못 댐`을 낸다.

이탈 회수 대상 항목은 `pick`이 발급한 토큰이 이미 소멸했을 수 있다. 토큰이 없으면 `pick`을 먼저 호출해 해당 항목의 토큰을 확보한 뒤 기록한다.

- **완료** → 아래 "완료와 수확"으로 간다.
- **하다 말았음** → 재진입 메모 한 줄만 받는다. 다른 것을 묻지 않는다.

  ```bash
  python scripts/simple_tasks.py complete "항목명" --token TOKEN --reentry "받은 메모"
  ```

  `--reentry`가 있으면 항목이 완료 처리되지 않고 메모만 갱신된다. 재진입 메모가 붙은 항목은 다음 `pick`에서 최우선으로 올라온다.

- **손도 못 댐** → 크기 보정 신호로 기록하고 바로 다음 카드를 낸다.

  ```bash
  python scripts/simple_tasks.py reject "항목명" --token TOKEN --reason abandon
  ```

## 완료와 수확

**여기가 이 시스템에서 유일하게 사용자에게 작성을 요구하는 지점이고, 유일하게 그것이 싼 순간이다.** 방금 실제로 무언가를 한 사용자는 심의 루프 밖에 있고 작업의 잔상이 남아 있다. 이 시점의 글쓰기는 결정이 아니라 회상이다.

자유 입력으로 두 칸을 받는다. 여기서만 선택지 도구를 쓰지 않는다.

```
완료. 방금 뭐 했는지 아직 머리에 있을 때 두 줄만.

다음에 이어서:   ___________________
하다가 떠오른 거: ___________________  (없으면 비워도 됨)
```

**두 칸을 모델이 미리 채워 주고 확인만 받으려 하지 말 것.** 사용자가 작업하며 알게 된 것("참고문헌 형식이 뒤죽박죽이더라", "3절은 데이터를 다시 받아야 함")은 추측이 불가능하다. 확인 버튼을 주면 사용자는 대충 넘기고 그 정보는 영영 사라진다. **입력 자체가 산출물인 지점에서 마찰을 없애면 산출물이 사라진다.**

형식을 요구하지 않는다. 마감이나 우선순위를 묻지 말고, 아무렇게나 쓴 문장을 그대로 받아 뒤에서 구조화한다. "형식 좀 갖춰서"라고 말하는 순간 이 창구도 비싸진다.

받은 내용을 그대로 넘긴다.

```bash
python scripts/simple_tasks.py complete "항목명" --token TOKEN --new-idea "둘째 칸 내용" --next
```

- **첫 칸이 비어 있으면** `--reentry`를 생략한다 → 항목이 완료로 이동한다.
- **첫 칸에 내용이 있으면** `--reentry "내용"`을 붙인다 → 항목이 남고 재진입 메모만 갱신된다. 아직 안 끝났다는 뜻이기 때문이다.
- **둘째 칸이 비어 있으면** `--new-idea`를 생략한다.

둘째 칸으로 들어온 항목에는 **방금 완료한 항목이 `spawned_by`로, 그 항목의 맥락이 `context`로 자동 기록된다.** 어디서 나온 생각인지 묻지 않는다 — 이미 알고 있다. 나중에 이 항목이 카드로 나갈 때 `why.spawned_by`가 "아까 보고서 하다가 나온 거"라는 `이유` 줄이 된다.

둘째 칸은 새 항목으로 추가되면서 자동으로 `묵힘` 표시가 붙는다. 던진 잡생각이 즉시 카드로 돌아오면 사용자는 "이거 쓰면 바로 시켜지는구나"를 학습하고 다음부터 쓰지 않는다. 묵힘은 다음 세션 `load`에서 자동으로 풀린다.

**수확이 끝나면 바로 다음 카드를 낸다.** 완료 직후가 관성이 가장 큰 순간이다. `--next`가 돌려준 `card`를 그대로 쓴다.

방금 수확한 새 아이디어는 `묵힘`이 붙어 자동으로 후보에서 빠지므로 다음 카드로 나오지 않는다. 목록에 다른 항목이 하나도 없을 때만 예외적으로 나온다.

## 너무 큼

같은 항목을 유지하고 **`시작` 줄만 한 단계 더 잘게** 만들어 재출력한다. 항목을 바꾸지 않는다.

```
1단계: 문서 열고 목차 3줄
2단계: 작년 보고서 열어서 목차만 훑기
3단계: 문서 열기
```

```bash
python scripts/simple_tasks.py reject "항목명" --token TOKEN --reason too_big --next
```

`too_big`은 언더스코어다. 하이픈으로 쓰면 크기 보정 집계에 잡히지 않는다.

돌아온 `card.name`이 같은 항목이면 `시작` 줄만 잘게 다시 쓴다. 다른 항목이 나왔으면 그것으로 새 카드를 만든다 — 오답도 촉매다. 토큰은 `card.token`으로 갱신된다.

같은 항목에 **2회까지만.** 3회째에는 항목 자체가 지금 할 게 아니라는 뜻이므로 아래 `다른 거`로 처리한다.

## 다른 거

**사유를 묻되, 다음 카드를 같은 턴에 이미 내놓은 상태로 묻는다.** 답을 기다린 뒤 카드를 만들면 그 대기 시간이 심의의 틈이 된다.

사유 선택지: `자료 없음` / `마음이 안 감` / `더 급한 게 있음` / `그냥 아님`. 타이핑을 요구하지 않는다.

받은 사유를 **그대로** 넘긴다. 한국어 문자열이 그대로 기록되고 크기 보정이 이를 읽는다.

```bash
python scripts/simple_tasks.py reject "항목명" --token TOKEN --reason "자료 없음" --next
```

같은 항목에 `자료 없음`이 2회 쌓이면 그 항목은 `준비 필요`로 표시되어 후보에서 내려간다. 사유를 뭉뚱그려 `other`로 넘기면 이 보정이 동작하지 않는다.

**`--next`가 `no_candidates`를 돌려주면** 낼 다음 카드가 없다는 뜻이다. 이때는 **질문 문구만 바꿔** 사유와 항목을 한 턴에 받는다 — 절차는 [references/modes.md](modes.md)의 "콜드 스타트에서의 반응 처리"에 있다. 선택지 도구의 자유 입력 칸이 항목을 받아 주므로 턴이 늘지 않는다.

**후보가 있는 세션에서는 문구를 바꾸지 않는다.** 낼 카드가 있는데 목록을 채우려 드는 것은 조사다.

## 라운드 상한

카드 제시는 **한 세션에 3회까지.** 그 이상은 카드 고르기 자체가 새로운 심의가 된다. 라운드 수는 스크립트가 세지 않으므로 이 세션 안에서 직접 센다.

3회를 넘기면 진단이 바뀐다. 추천이 틀린 게 아니라 목록이 낡았거나 오늘 일할 상태가 아닌 것이다.

```
세 개 다 아니면 오늘 목록이 낡았거나 지금 할 때가 아니야.
```

선택지: `목록 정리하기` / `10분 뒤에 다시`. 이것이 무한 반복보다 정직하고 사용자도 납득한다.

## 오늘 그만

```bash
python scripts/simple_tasks.py end-session
```

짧게 끊는다. 격려도 요약도 하지 않는다.

`오늘 그만`이 반드시 선택지에 있어야 한다. 없으면 완료할수록 새 카드가 나오는 러닝머신이 되고, 사용자는 완료 버튼을 안 누르는 방식으로 도망친다. 그러면 수확 경로가 통째로 막힌다.

열린 카드는 그대로 남아 다음 세션의 이탈 회수 대상이 된다.
