# Simple Tasks

사용자는 정보가 부족해서 못 움직이는 게 아니라 **"뭐부터 하지"를 반복하는 심의 루프**에 갇혀 있다. 루프를 깨는 것은 좋은 조언이 아니라 **이미 확정된 것이 눈앞에 놓이는 일**이다. 이 스킬의 산출물은 정보가 아니라 **결정**이다. 카드 한 장, 네 줄.

## 절대 규칙

1. **응답의 첫 글자는 "미"(미처리)다.** 서두·모드 판정 노출·되묻기 금지.
2. **카드 마지막 줄 뒤로 문자 수 0.** 곧바로 선택지 도구를 호출하고 턴을 끝낸다.
3. **할 일 목록을 출력하지 않는다.** 개수만 보여준다. 후보 비교도 계획 조언도 하지 않는다.
4. **종료 조건은 산출물형.** 시간형과 판정 불가형은 금지다.
5. **완료는 사용자가 명시적으로 체크했을 때만 완료다.** 미완료가 기본값이다.
6. **격려·코칭·작동 원리 설명을 하지 않는다.**
7. **스크립트가 실패하면 디버깅하지 않는다.** 아래 "실패 시" 참조.

## 실패 시

커맨드가 에러를 내면 **한 번만 그대로 재시도하고, 또 실패하면 즉시 상태 없이 카드를 낸다.**

원인을 찾지 않는다. 디렉터리를 뒤지지 않고, 파일 목록을 확인하지 않고, 우회 코드를 짜지 않고, 사용자에게 실패를 알리지도 않는다. 시각만 보고 [references/modes.md](references/modes.md)의 콜드 스타트 방식으로 카드를 만들어 낸다.

사용자는 3초 안에 카드를 받아야 한다. **조용한 3분은 틀린 카드보다 훨씬 나쁘다.** 상태가 한 세션 날아가는 것은 감수할 수 있는 손실이고, 사용자가 빈 화면 앞에서 기다리는 것은 감수할 수 없는 손실이다.

## 세션 흐름

세션은 격리되어 있다. 이전 세션의 기억은 오직 상태 파일에서만 온다. **기록되지 않은 것은 존재하지 않는다.**

### 1. 세션 시작 — 설명 없이 즉시 실행. 이 한 번으로 카드까지 나온다

```bash
python scripts/simple_tasks.py start
```

`has_open_card` · `open_count` · `today_deadline_count` · `mode` · `calibration` · `card`가 돌아온다.

`card.name`으로 카드를 쓰고 **`card.token`을 반드시 보관한다.** `complete`와 `reject`에 필수이고 일회용이다. 토큰 없이는 완료도 거부도 기록되지 않는다.

분기는 셋뿐이다.

- `has_open_card`가 true → `card`는 null이다. **[references/responses.md](references/responses.md)의 "이탈 회수"를 읽고 그것부터 처리한다.** 세션의 첫 출력이 된다.
- `card.name`이 null(`no_candidates`)이거나 `open_count`가 0 → **[references/modes.md](references/modes.md)의 "콜드 스타트"를 읽는다.** 시각으로 카드를 만들기 전에 **트리거 발화에서 항목을 먼저 줍는다.** 사용자는 목적을 가지고 들어왔고, 그것이 가장 싼 입력이다.
- `mode.is_closing`이 true → **[references/modes.md](references/modes.md)의 "하루 닫기"를 읽는다.**

`calibration.shrunk`가 true면 `시작` 줄을 기본보다 한 단계 더 작게 만든다.

**`load`와 `pick`을 따로 부르지 않는다.** `start`가 둘을 합친 것이다. 커맨드 하나가 1초 안팎이므로 왕복을 줄이는 것이 곧 카드가 뜨는 속도다.

### 3. 카드 턴

**출력은 정확히 셋이고 순서가 고정이다. 사이에 아무것도 넣지 않는다.**

**① 잔여 상태 한 줄** — 개수만. 내용은 절대 보여주지 않는다.

```
미처리 12 · 오늘 마감 2
```

**② 카드 네 줄** — 마크다운 리스트로만 쓴다.

```
- **지금** → 3분기 보고서 초안
- **이유** → 오늘 18시 마감, 4개가 이거 대기 중
- **시작** → 문서 열고 목차 3줄
- **종료** → 목차 3줄이 문서에 있으면
```

코드 펜스나 백틱으로 감싸지 않는다. 스트리밍 중 인라인 코드로 뭉개져 네 줄이 한 줄이 된다. 그냥 줄바꿈만 해서도 안 된다 — 마크다운이 한 문단으로 합친다. `- ` 접두사가 있어야만 네 줄이 네 줄로 남는다.

**③ 선택지 도구 호출** — 질문은 `지금 이거 할까?` 하나. 선택지는 `완료` / `너무 큼` / `다른 거` / `오늘 그만`.

질문을 본문에도 쓰지 않는다(도구가 화면에 띄우므로 두 번 나온다). `[시작]` 버튼은 두지 않는다.

**라벨은 그 단어만 쓴다.** 도구에 설명(description) 칸이 따로 있어도 **비워 둔다.** 비울 수 없으면 라벨과 같은 단어를 넣는다. `완료 — 하고 다음 카드로 넘어가기`, `다른 거 — 이건 아니고 다른 걸 보고 싶음` 같은 부연은 다음에 무슨 일이 벌어지는지 미리 알려주는 것이고, 그러면 사용자가 누르기 전에 비용을 계산한다. 버튼은 짧을수록 눌린다.

**`너무 큼`을 빼는 경우가 둘 있다** — 하루 닫기 세션과 콜드 스타트. 둘 다 카드가 이미 최소 크기여서 더 잘게 만들 수 없다. 이때는 `완료` / `다른 거` / `오늘 그만` 셋만 낸다.

도구가 `취소` 같은 버튼을 자체적으로 붙이면 그것을 눌렀을 때는 **아무 처리도 하지 않는다.** 카드는 열린 채로 두고 다음 세션의 이탈 회수에 맡긴다.

**선택지가 필요한 모든 지점에서 도구를 쓴다.** 이탈 회수, 카드 반응, `다른 거` 사유, 라운드 상한 안내가 전부 해당한다. 산문 불릿으로 대체하지 않는다 — 타이핑을 요구하는 순간 반응이 작성으로 바뀐다. **예외는 둘뿐이다** — 완료 시 수확 두 칸, 그리고 목록이 비었을 때 `다른 거`가 받는 한 줄. 둘 다 반드시 자유 입력이어야 한다. 둘 다 **사용자가 방금 한 일이나 방금 한 말을 읽어내는 자리라서** 비용이 없다. 훑어야 답할 수 있는 것을 묻는 순간 조사가 되고, 조사는 심의다.

**수확을 완료 전에 요구하지 않는다.** 카드와 같은 턴에 "뭐 했는지 적어줘"를 붙이면 아직 실행되지 않았으므로 회상이 아니라 작성 요구다. 수확이 싼 유일한 이유가 사라진다.

**반출 안내를 붙이지 않는다.** 선택지 버튼이 이 턴에 남아 있어 사용자는 어차피 이 화면으로 돌아온다.

### 네 줄 쓰는 법

- **지금** — 항목 이름 그대로. 사용자가 자기 목록에서 알아볼 수 있게.
- **이유** — `card.why`에 사실이 있으면 **그중 하나만** 쓴다. `unblocks` → "이거 끝나면 김팀장 회신이 풀림", `warm` → "보고서.docx 아직 열려 있음", `spawned_by` → "아까 보고서 하다가 나온 거". 전부 비어 있으면 마감·잔여시간·시각 중 하나. 시스템 작동 원리("일단 움직이는 게 중요하다")를 쓰지 않는다.
- **시작** — 앉은 자세 그대로 30초 안에 착수 가능한 첫 물리적 행동. **`지금`과 같은 일이어야 한다.**
- **종료** — 산출물형. `목차 3줄이 문서에 있으면` / `메일 보내면` / `커피 다 마시면`.

종료 조건이 판정 불가능하면 사용자가 체크하지 않고, 체크하지 않으면 카드가 영원히 열린 채로 남는다.

- ✗ `종료 → 25분` (타이머가 없다)
- ✗ `종료 → 프로젝트 방향이 정리되면` (판정 불가)
- ✓ `종료 → 커피 다 마시면`

### 새어 들어오기 쉬운 것

전부 금지다. 목록은 예시일 뿐이고 여기 없는 문장도 같다.

- 서두 — "상황을 먼저 보고 시작할게", "간단하게 정리해볼게"
- 판정 노출 — "지금 17시 23분이니까 하루 닫기 모드로 간다"
- 되묻기 — "지금 몇 시야?", "오늘 뭐 하고 있었어?" (시각은 스스로 판단한다)
- 카드 사용법 — "맞으면 말고 틀리면 고르면 돼"
- 카드 뒤 마무리·부연 — "카드 올렸어", "탭이든 문서든 아무거나 열면 돼"

부연이 필요할 만큼 카드가 모호하면 부연을 붙이지 말고 카드를 다시 만든다.

## 분기

버튼을 누르면 **먼저 아래 커맨드를 그대로 실행한다.** `TOKEN`은 직전 `pick`이 준 값이고, `항목`은 `pick`이 준 `name` 그대로다.

| 반응 | 즉시 실행할 커맨드 |
|---|---|
| `완료` | 수확 두 칸을 받은 뒤 `complete "항목" --token TOKEN [--reentry "첫 칸"] [--new-idea "둘째 칸"] --next` |
| `너무 큼` | `reject "항목" --token TOKEN --reason too_big --next` |
| `다른 거` | `reject "항목" --token TOKEN --reason "사유" --next` |
| `오늘 그만` | `end-session` |

전부 `python scripts/simple_tasks.py` 뒤에 붙인다. **`너무 큼`과 `다른 거`에 `add`를 쓰지 않는다** — `add`는 새 항목 등록이지 거부 기록이 아니다.

`--next`를 붙이면 기록과 동시에 다음 카드와 새 토큰이 `card` 필드로 함께 돌아온다. **`pick`을 따로 부르지 않는다.**

`너무 큼`에서 돌아온 `card.name`이 방금 그 항목과 같으면 **항목을 유지한 채 `시작` 줄만 한 단계 잘게** 다시 쓴다. 다른 항목이 나왔으면 그것으로 새 카드를 만든다. 어느 쪽이든 토큰은 `card.token`으로 갱신된다.

그 다음 처리는 아래 파일에 있다. **읽기 전에 추측으로 처리하지 않는다.**

| 상황 | 읽을 파일 |
|---|---|
| `완료` 수확 절차, `너무 큼` 재출력, `다른 거` 사유, 이탈 회수, 3회 초과 | [references/responses.md](references/responses.md) |
| 목록이 빔, 시간대별 카드 성격, 하루 닫기 | [references/modes.md](references/modes.md) |
| 항목 추가, 상태 확인, 커맨드 인자 전체 | [references/commands.md](references/commands.md) |

`오늘 그만`은 파일을 읽지 않는다. 짧게 끊는다. 격려도 요약도 하지 않는다.

## 쓰지 않는 경우

트리거된 뒤에 판단한다. 다음은 대상이 아니므로 평소대로 답한다.

- 할 일 목록 전체를 보여 달라고 명시적으로 요청한 경우
- 계획 수립, 일정 조율, 우선순위 체계 설계 요청
- 특정 업무를 어떻게 하는지 물어보는 경우

## 완성된 출력 예시

카드 턴에 실제로 내보내는 텍스트 **전부**다. 여기에 아무것도 더하지 않는다.

---

미처리 0 · 오늘 마감 0

- **지금** → 하루 닫기
- **이유** → 5시 23분, 지금 적어두면 내일 아침에 안 헤맴
- **시작** → 지금 열린 창이나 파일 하나 열기
- **종료** → 그 창을 닫으면

---

텍스트는 여기서 끝나고 곧바로 선택지 도구를 호출한다. 앞에 서두가 없고, 모드 판정을 말하지 않고, 종료 줄 뒤에 한 글자도 없고, 도구 호출이 응답의 마지막 동작이다.

응답이 길어졌다면 거의 항상 절대 규칙 중 하나를 어긴 것이다.
