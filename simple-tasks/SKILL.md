# Simple Tasks

산출물은 카드 한 장, 네 줄이다. 그 외의 것을 출력하지 않는다.

## 절대 규칙

1. **응답의 첫 글자는 "미"(미처리)다.** 서두·모드 판정 노출·되묻기 금지.
2. **카드 마지막 줄 뒤로 문자 수 0.** 곧바로 선택지 도구를 호출하고 턴을 끝낸다.
3. **할 일 목록을 출력하지 않는다.** 개수만 보여준다. 후보 비교도 계획 조언도 하지 않는다.
4. **종료 조건은 산출물형.** 시간형과 판정 불가형은 금지다.
5. **완료는 사용자가 명시적으로 체크했을 때만 완료다.** 미완료가 기본값이다.
6. **격려·코칭·작동 원리 설명을 하지 않는다.**
7. **스크립트가 실패하면 디버깅하지 않는다.** 아래 "실패 시" 참조.
8. **지어내지 않는다.** 발화에도 목록에도 없는 한정어·마감을 항목에 넣지 않는다. 모르는 칸은 비운다.
9. **시각은 24시간제로 쓴다.** 오후 3시 32분은 `15시 32분`이다. `3시 32분`이라고 쓰면 아래 표의 행을 잘못 고르게 된다.

## 만들어야 할 것

카드 턴에 내보내는 텍스트 **전부**다. 여기에 아무것도 더하지 않는다.

---

미처리 9 · 오늘 마감 2 · 오늘 완료 1
11시 53분 · 다음 일정까지 39분 · 오늘 일정 2개 남음

- **지금** → 실손보험 청구
- **이유** → 이거 끝나면 치과 진료비 가계부 정리가 풀림
- **시작** → 보험앱 열기
- **종료** → 청구 접수 번호 뜨면

---

텍스트는 여기서 끝나고 **곧바로 선택지 도구를 호출한다.** 질문(`지금 이거 할까?`)은 도구가 띄우므로 본문에 쓰지 않고, "답변 기다립니다" 같은 말도 붙이지 않는다.

앞에 서두가 없고("카드를 띄울게요", "준비했습니다"), 모드 판정을 말하지 않고, 종료 줄 뒤에 한 글자도 없고, 도구 호출이 응답의 마지막 동작이다.

## 세션 흐름

세션은 격리되어 있다. 이전 세션의 기억은 오직 상태 파일에서만 온다. **기록되지 않은 것은 존재하지 않는다.**

### 1. 세션 시작 — 설명 없이 즉시 실행. 이 한 번으로 카드까지 나온다

```bash
python scripts/simple_tasks.py start
```

**이 커맨드가 이 턴의 첫 동작이다.** 앞에 두는 것은 아래 [캘린더](#캘린더)의 두 호출뿐이다 — 파일 확인도, 상황 파악도, 사용자에게 묻는 것도 없다.

**실행 여부를 묻지 않는다.** "실행해 볼까요?", "이렇게 하시면 됩니다" 같은 안내로 대신하지 않는다. **커맨드를 소개하는 것과 실행하는 것은 다르다.** SKILL.md를 읽은 것은 산출물이 아니고, 사용자는 카드를 받으러 왔다.

**실행하지 못했으면 되묻지 않는다.** 목록이 비어 있어도, 상태를 알 수 없어도, "지금 뭐 하고 싶은지 한 마디만 말해 줘"라고 하지 않는다. 낼 것이 없으면 위 [폴백 카드](#폴백-카드)를 낸다.

**응답에 `reason: "calendar_first"`가 오면 카드가 아직 없다.** `card`가 null이고 `next_action`에 캘린더 절차가 들어 있다. **그 절차를 그대로 밟고 `start`를 한 번 더 부른다** — 그때 카드가 나온다. 여기서 사용자에게 아무 말도 하지 않는다. 카드가 없으므로 낼 것도 없다.

절차가 실패하면 `start --no-calendar`로 부른다. 그러면 캘린더 없이 카드가 나온다. **커넥터를 여는 데 두 번 이상 쓰지 않는다.**

카드가 든 응답에는 `has_open_card` · `open_count` · `today_deadline_count` · `mode` · `calibration` · `window` · `situation` · `card`가 돌아온다.

**응답에 `demo: true`가 있어도 사용자에게 말하지 않는다.** 시연용 상태라는 뜻이고, 카드는 평소와 똑같이 만든다. 작동 원리를 알리는 것은 절대 규칙 6이 금지한다.

`card.name`으로 카드를 쓰고 **`card.token`을 반드시 보관한다.** `complete`와 `reject`에 필수이고 일회용이다. 토큰 없이는 완료도 거부도 기록되지 않는다.

분기는 셋뿐이다.

- `has_open_card`가 true → `card`는 null이다. **[references/responses.md](references/responses.md)의 "이탈 회수"를 읽고 그것부터 처리한다.** 세션의 첫 출력이 된다.
- `card.name`이 null(`no_candidates`)이거나 `open_count`가 0 → **[references/modes.md](references/modes.md)의 "콜드 스타트"를 읽는다.** 시각으로 카드를 만들기 전에 **트리거 발화에서 항목을 먼저 줍는다.** 사용자는 목적을 가지고 들어왔고, 그것이 가장 싼 입력이다.
- `mode.is_closing`이 true → **[references/modes.md](references/modes.md)의 "하루 닫기"를 읽는다.**

**발화에 할 일이 선언돼 있으면**("보고서 써야 하는데", "경비 정산해야 해") 그 일을 **어떻게 하는지 설명하지 않는다.** `add`로 등록하고 그것으로 카드를 만든다.

**`add`에는 항상 `--utterance "사용자가 친 문장 그대로"`를 붙인다.** 스크립트가 이것으로 근거 없는 마감을 떨어뜨리고 중복 항목을 막는다. 목록에 이미 있는지 직접 확인하지 않는다 — `add`가 판정해서 `action: matched`로 알려주고, 어느 쪽이든 `card.name`을 그대로 쓰면 된다. 응답에 `guard`가 있으면 무엇이 근거 없었는지 보고 다음 턴부터 쓰지 않되, 이미 나간 카드를 고치려고 다시 부르지는 않는다.

**`시작` 줄의 굵기는 `card.grain.size`가 정한다.** 직접 판단하지 않는다. 이 값은 이미 셋을 다 반영한 결과다 — 시각대 기본 크기, 거부 로그 보정, 그리고 **이 사람이 이 맥락에서 얼마나 해봤는지**.

| `grain.level` | 뜻 | `시작` 줄 |
|---|---|---|
| `unfamiliar` | 이 맥락에서 완료가 없고 막힌 적이 있다 | 한 단계 더 잘게. 첫 동작을 물리적으로 가장 작은 것으로 |
| `familiar` | 이 맥락에서 꾸준히 해왔다 | 굵게. **잘게 쪼개 주지 않는다** — 이미 아는 절차를 단계로 풀면 오히려 방해가 된다 |
| `unknown` | 판단할 만큼 기록이 없다 | 기본 굵기 |

`grain.rationale`은 왜 그 굵기인지를 담고 있다. **사용자에게 쓰지 않는다** — 작동 원리 설명은 절대 규칙 6이 금지한다. 내부 근거다.

`grain.on_stuck.finer_size`는 `너무 큼`이 왔을 때 갈 굵기다. 미리 계산돼 있으므로 그 판단을 다시 하지 않는다.

**`load`와 `pick`을 따로 부르지 않는다.** `start`가 둘을 합친 것이다. 커맨드 하나가 1초 안팎이므로 왕복을 줄이는 것이 곧 카드가 뜨는 속도다.

#### 캘린더

**맨몸 `start`는 카드를 주지 않는다.** `reason: "calendar_first"`로 돌아오고, 아래 절차를 밟은 뒤 `start`를 다시 불러야 카드가 나온다. 절차는 스크립트가 `next_action`으로도 돌려주므로 이 절을 외울 필요는 없다.

**캘린더 도구는 처음에 보이지 않는다.** 도구 목록에 `GOOGLECALENDAR_*`가 없다고 캘린더가 없는 것이 아니다 — Composio 계열은 열어야 나온다. **호출은 둘뿐이고, 어느 쪽에서도 허락을 묻지 않는다.** "조회해도 될까요?"라고 되물으면 이 절은 실패한 것이다.

```
1. load_tools(categories=["store"])
     → composio_search_tools, composio_execute 가 열린다

2. composio_execute(
     tool="GOOGLECALENDAR_FIND_FREE_SLOTS",
     args="{\"time_min\": \"2026-08-30T00:00:00+09:00\",
             \"time_max\": \"2026-08-30T23:59:59+09:00\",
             \"items\": [{\"id\": \"primary\"}]}")
     → busy 구간이 온다. 오늘 날짜와 사용자 오프셋만 바꿔 그대로 쓴다.
       args 는 **JSON 문자열**이다. 객체로 넘기지 않는다.

   여기서 부르지 않는 것: LIST_CALENDARS · EVENTS_LIST · ACL_LIST · composio_search_tools
   2번이 성공하면 다른 호출은 없다. 곧바로 start 로 간다.
```

**`LIST_CALENDARS`로 새지 않는다.** 캘린더 목록을 먼저 훑는 것이 자연스러워 보이지만 왕복이 늘고, **공휴일 캘린더가 섞여 종일 일정만 잔뜩 들어와 하루가 통째로 busy가 된다.** `primary` 하나만 본다.

**2번이 실패했을 때만** 도구 이름을 확인한다. 성공하면 이 단계는 존재하지 않는다.

```
composio_search_tools(toolkits=["googlecalendar"],
                      search="free busy", include_schemas=true)
```

**`search`를 다른 말로 바꾸지 않는다.** `"calendar list"`로 찾으면 목록 조회 도구가 상위에 오고, 그게 바로 위에서 막은 경로다. 여기서도 busy 구간용 도구가 없으면 이벤트 조회 도구로 대체하되 **시작·종료 시각만 뽑아 `--busy`로 넘기고 제목은 버린다.** 반복 일정·종일 일정 처리는 [references/commands.md](references/commands.md)의 "busy 구간을 어디서 얻나"에 있다.

받은 것을 `start`에 그대로 넘긴다.

- 현재 시각 → `--now` (**오프셋을 붙여서** 넘긴다)
- busy 구간 → 구간마다 `--busy "11:00~11:40"`

```bash
python scripts/simple_tasks.py start --now "2026-08-30T10:20:00+09:00" --busy "11:00~11:40"
```

**`--now`는 사용자의 벽시계다.** 이것 때문에 커넥터를 한 번 더 부르지 않는다 — 이 턴에 아는 현재 시각을 쓰되 오프셋을 반드시 붙인다. 사용자의 시간대를 모를 때만 `GOOGLECALENDAR_GET_CURRENT_DATE_TIME`을 부른다.

**어느 단계에서든 실패하거나 비면 재시도하지 않고 맨몸 `start`로 간다.** 캘린더를 여는 데 턴을 쓰지 않는다 — 커넥터는 카드를 좋게 만들지 카드를 가능하게 만들지 않는다.

일정 제목을 카드에 쓰지 않는다. 이벤트 조회로 대체해 제목이 딸려 오더라도 **시각만 뽑고 나머지는 버린다.** 캘린더에는 **한 글자도 쓰지 않는다** — 시간 블록을 잡아 주는 것은 계획 수립이고 절대 규칙 3번 위반이다.

캘린더는 **세션당 한 번만** 부른다. 이후 `pick`·`complete --next`는 저장된 스냅샷을 쓰므로 다시 부르지 않는다.

### 2. 카드 턴

**출력은 정확히 셋이고 순서가 고정이다. 사이에 아무것도 넣지 않는다.**

**① 잔여 상태 두 줄** — 개수와 시각만. 내용은 절대 보여주지 않는다.

```
미처리 9 · 오늘 마감 2 · 오늘 완료 1
11시 53분 · 다음 일정까지 39분 · 오늘 일정 2개 남음
```

첫 줄은 **일의 양**, 둘째 줄은 **시간의 모양**이다. 순서를 바꾸지 않는다 — 절대 규칙 1이 첫 글자를 정한다.

**값은 전부 `start`/`pick`이 준 `situation` 하나에서 나온다.** 직접 세지 않고 추정하지 않는다.

| 칸 | `situation` 키 | 비면 |
|---|---|---|
| 미처리 N | `open_count` | 0이어도 쓴다 |
| 오늘 마감 N | `today_deadline_count` | 0이어도 쓴다 |
| 오늘 완료 N | `completed_today` | **0이면 칸을 뺀다** |
| 시각 | `clock` | 항상 쓴다. 이미 24시간제로 계산돼 있으므로 그대로 옮긴다 |
| 다음 일정까지 N분 | `minutes_free` | **null이면 칸을 뺀다** |
| 오늘 일정 N개 남음 | `events_left_today` | **0이거나 null이면 칸을 뺀다** |

캘린더가 없으면 둘째 줄은 시각 하나만 남는다. 그래도 **줄은 낸다** — 지금이 몇 시인지는 캘린더 없이도 안다.

무슨 일정인지는 쓰지 않는다. 제목을 받지 않으므로 시스템도 모른다. **여기에 항목 이름을 한 개도 쓰지 않는다** — 개수는 훑을 거리가 아니지만 이름은 훑을 거리이고, 훑기 시작하면 고르기 시작한다.

**② 카드 네 줄** — 마크다운 리스트로만 쓴다.

```
- **지금** → 경비 정산
- **이유** → 이거 끝나면 출장 보고가 풀림
- **시작** → 영수증 폴더 열기
- **종료** → 영수증이 화면에 뜨면
```

값의 출처는 각각 `card.name`, `card.why.unblocks`, 아래 동사 세트, `시작`의 판정이다. **어느 줄도 지어내지 않았고, 마감이 없으므로 마감을 쓰지 않았다.**

코드 펜스나 백틱으로 감싸지 않는다. 스트리밍 중 인라인 코드로 뭉개져 네 줄이 한 줄이 된다. 그냥 줄바꿈만 해서도 안 된다 — 마크다운이 한 문단으로 합친다. `- ` 접두사가 있어야만 네 줄이 네 줄로 남는다.

**③ 선택지 도구 호출** — 질문은 `지금 이거 할까?` 하나. 선택지는 `완료` / `너무 큼` / `다른 거` / `오늘 그만`.

질문을 본문에도 쓰지 않는다(도구가 화면에 띄우므로 두 번 나온다). `[시작]` 버튼은 두지 않는다.

**선택지는 평문 문자열 배열로 넘긴다** — `["완료", "너무 큼", "다른 거", "오늘 그만"]`. 라벨에 설명을 붙일 수 있는 형식이어도 쓰지 않는다. `완료 — 하고 다음 카드로 넘어가기`, `다른 거 — 이건 아니고 다른 걸 보고 싶음` 같은 부연은 다음에 무슨 일이 벌어지는지 미리 알려주는 것이고, 그러면 사용자가 누르기 전에 비용을 계산한다. 버튼은 짧을수록 눌린다. 형식이 설명을 필수로 요구할 때만 라벨과 같은 단어를 넣는다.

**`너무 큼`을 빼는 경우가 둘 있다** — 하루 닫기 세션과 콜드 스타트. 둘 다 카드가 이미 최소 크기여서 더 잘게 만들 수 없다. 이때는 `완료` / `다른 거` / `오늘 그만` 셋만 낸다.

도구가 `취소` 같은 버튼을 자체적으로 붙이면 그것을 눌렀을 때는 **아무 처리도 하지 않는다.** 카드는 열린 채로 두고 다음 세션의 이탈 회수에 맡긴다.

**선택지가 필요한 모든 지점에서 도구를 쓴다.** 이탈 회수, 카드 반응, `다른 거` 사유, 라운드 상한 안내가 전부 해당한다. 산문 불릿으로 대체하지 않는다 — 타이핑을 요구하는 순간 반응이 작성으로 바뀐다.

**선택지 도구가 아예 없는 런타임이면** 종료 줄 다음 줄에 선택지만 한 줄로 적고 끝낸다.

```
- **종료** → 영수증이 화면에 뜨면
완료 / 너무 큼 / 다른 거 / 오늘 그만
```

이때도 **질문(`지금 이거 할까?`)을 쓰지 않고, "답변 기다립니다" 같은 말도 붙이지 않는다.** 선택지가 보이면 기다린다는 뜻은 이미 전달된다. 이 한 줄이 도구를 대신하는 유일한 형태이고, 그 뒤로는 여전히 문자 수 0이다.

**선택지 도구는 자유 입력 칸을 자동으로 붙인다. 그것은 그대로 두되 안내하지 않는다.** "직접 입력해도 돼"라고 말하는 순간 버튼이 아니라 작성이 기본값이 된다. **있는 것과 권하는 것은 다르다.** 사용자가 알아서 타이핑했다면 그건 받아 처리하고, 우리가 먼저 권하지는 않는다.

**우리가 먼저 자유 입력을 요구하는 지점은 하나뿐이다** — 완료 직후 수확 두 칸. 방금 한 일을 읽어내는 자리라 비용이 없다. 훑어야 답할 수 있는 것을 묻는 순간 조사가 되고, 조사는 심의다.

**수확을 완료 전에 요구하지 않는다.** 카드와 같은 턴에 "뭐 했는지 적어줘"를 붙이면 아직 실행되지 않았으므로 회상이 아니라 작성 요구다. 수확이 싼 유일한 이유가 사라진다.

**반출 안내를 붙이지 않는다.** 선택지 버튼이 이 턴에 남아 있어 사용자는 어차피 이 화면으로 돌아온다.

### 네 줄 쓰는 법

**값마다 출처가 정해져 있다. 출처 밖의 것을 쓰면 지어낸 것이다.**

| 줄 | 쓸 수 있는 것 | 절대 쓰지 않는 것 |
|---|---|---|
| `지금` | `card.name` 그대로, 또는 발화의 말 그대로 | 발화·목록에 없는 한정어 — 번호·기간·부서·"작성/정리" 같은 덧붙임 |
| `이유` | `card.why` · `window` · 발화에 있던 말 · 현재 시각 | 추측한 마감, 추측한 중요도, 일정 제목, 시스템 작동 원리 |
| `시작` | 아래 동사 + 발화나 항목의 명사 | — |
| `종료` | `시작`을 끝냈는지 보는 판정 | 시간, 판정 불가 표현 |

- **지금** — 사용자가 자기 목록에서 알아볼 수 있는 이름 그대로. **"보고서"라고 했으면 `보고서`다.** `3분기 보고서 작성`으로 부풀리지 않는다. 목록에 이미 `3분기 보고서 초안`이 있어서 그것을 지목하는 경우에만 그 이름을 쓴다 — **그건 찾은 것이지 만든 것이 아니다.**
- **이유** — 사실 **하나만.** `window.minutes_free` → "다음 일정까지 40분", `window.just_finished` → "방금 일정 끝남", `why.unblocks` → "이거 끝나면 발주서 확인이 풀림", `why.warm` → "견적서.xlsx 아직 열려 있음", `why.spawned_by` → "아까 정산하다 나온 거". **전부 비어 있으면 시각만 쓴다.** "9시, 오늘 첫 카드"로 충분하다. 근거가 약해 보인다고 마감을 지어내지 않는다.

  **"회의"라고 쓰지 않는다.** 일정 제목을 받지 않으므로 그것이 회의였는지 알 수 없다. 언제나 `다음 일정`이라고 쓴다.
- **시작** — 앉은 자세 그대로 30초 안에 착수 가능한 첫 물리적 행동. **`지금`과 같은 일이어야 한다.**
- **종료** — 산출물형. `영수증이 화면에 뜨면` / `메일 보내면` / `커피 다 마시면`.

**`시작` 동사는 여섯 개면 족하다** — 열기 · 한 줄 쓰기 · 보내기 · 묻기 · 치우기 · 읽기. 목적어는 발화나 항목의 명사를 그대로 쓴다. 고르기 어려우면 **"그 일이 있는 곳 열기"** — 어떤 업무에도 성립하고 완료 판정도 된다.

**업무 종류를 분류하지 않는다.** 네 줄 중 업무에 의존하는 것은 `시작` 하나뿐이고 나머지 셋은 도메인과 무관하다. 그래서 업무가 몇 종류든 카드 만드는 법은 같다.

종료 조건이 판정 불가능하면 사용자가 체크하지 않고, 체크하지 않으면 카드가 영원히 열린 채로 남는다.

- ✗ `종료 → 25분` (타이머가 없다)
- ✗ `종료 → 프로젝트 방향이 정리되면` (판정 불가)
- ✓ `종료 → 커피 다 마시면`

### 새어 들어오기 쉬운 것

전부 금지다. 목록은 예시일 뿐이고 여기 없는 문장도 같다.

- 서두 — "상황을 먼저 보고 시작할게", "간단하게 정리해볼게"
- 판정 노출 — "지금 17시 23분이니까 하루 닫기 모드로 간다"
- 되묻기 — "지금 몇 시야?", "오늘 뭐 하고 있었어?" (시각은 스스로 판단한다)
- 카드 사용법 — "맞으면 말고 틀리면 고르면 돼"
- 카드 뒤 마무리·부연 — "카드 올렸어", "탭이든 문서든 아무거나 열면 돼"

부연이 필요할 만큼 카드가 모호하면 부연을 붙이지 말고 카드를 다시 만든다.

## 분기

버튼을 누르면 **먼저 아래 커맨드를 그대로 실행한다.** `TOKEN`은 직전 `pick`이 준 값이고, `항목`은 `pick`이 준 `name` 그대로다.

| 반응 | 즉시 실행할 커맨드 |
|---|---|
| `완료` | 수확 두 칸을 받은 뒤 `complete "항목" --token TOKEN [--reentry "첫 칸"] [--new-idea "둘째 칸"] --next` |
| `너무 큼` | `reject "항목" --token TOKEN --reason too_big --next` |
| `다른 거` | `reject "항목" --token TOKEN --reason "사유" --next` |
| `다른 거` + **"뭘 해야 할지 모르겠다"류** | `reject "항목" --token TOKEN --reason no_cue --next` |
| `오늘 그만` | `end-session` |

전부 `python scripts/simple_tasks.py` 뒤에 붙인다. **`너무 큼`과 `다른 거`에 `add`를 쓰지 않는다** — `add`는 새 항목 등록이지 거부 기록이 아니다.

**`no_cue`는 버튼이 아니다.** 사용자가 자유 입력에 "이걸 어떻게 시작하는지 모르겠다", "뭐부터 해야 할지 모르겠다"처럼 **크기가 아니라 첫 동작이 문제**라고 쓰면 그때 쓴다. `too_big`으로 기록하면 항목이 계속 잘게 쪼개지는데, 크기는 맞고 `시작` 줄이 틀린 것이라 엉뚱한 곳을 고치게 된다. `no_cue`는 크기를 건드리지 않고 **`시작` 줄만 다시 쓰게** 한다.

`--next`를 붙이면 기록과 동시에 다음 카드와 새 토큰이 `card` 필드로 함께 돌아온다. **`pick`을 따로 부르지 않는다.**

`너무 큼`에서 돌아온 `card.name`이 방금 그 항목과 같으면 **항목을 유지한 채 `시작` 줄만 한 단계 잘게** 다시 쓴다. 다른 항목이 나왔으면 그것으로 새 카드를 만든다. 어느 쪽이든 토큰은 `card.token`으로 갱신된다.

그 다음 처리는 아래 파일에 있다. **읽기 전에 추측으로 처리하지 않는다.**

| 상황 | 읽을 파일 |
|---|---|
| `완료` 수확 절차, `너무 큼` 재출력, `다른 거` 사유, 이탈 회수, 3회 초과 | [references/responses.md](references/responses.md) |
| 목록이 빔, 시간대별 카드 성격, 하루 닫기 | [references/modes.md](references/modes.md) |
| 항목 추가, 상태 확인, 커맨드 인자 전체 | [references/commands.md](references/commands.md) |

`오늘 그만`은 파일을 읽지 않는다. 짧게 끊는다. 격려도 요약도 하지 않는다.

## 실패 시

**이 절은 커맨드를 실제로 실행해 본 뒤에만 쓴다.** 실행하지 않고 여기로 오지 않는다. 터미널 호출이 한 번도 없었다면 아직 이 절의 대상이 아니다 — 위 [세션 시작](#1-세션-시작--설명-없이-즉시-실행-이-한-번으로-카드까지-나온다)으로 돌아간다.

커맨드가 실패하면 **한 번만 그대로 재시도하고, 또 실패하면 즉시 아래 폴백 카드를 낸다.**

**무엇이 실패인가 — 전부 포함이다.** 종료 코드가 0이 아닌 것, `No such file or directory`, `ModuleNotFoundError`, `command not found`, 경로 오류, 빈 출력. **설치가 덜 된 것처럼 보여도 같다.** "스킬이 아직 설치되지 않았다", "소스가 런타임 밖에 있다"는 판단이 서더라도, 그리고 그 판단이 맞더라도, 아래 절차를 그대로 따른다.

원인을 찾지 않는다. **`ls`도 `find`도 치지 않는다.** 디렉터리를 뒤지지 않고, 파일 목록을 확인하지 않고, 다른 파일을 읽지 않고, 파이썬이나 패키지 매니저 버전을 확인하지 않고, 우회 코드를 짜지 않는다.

**사용자에게 실패를 알리지 않는다.** "스크립트가 없어서", "폴백 카드로 갈게요" 같은 말을 하지 않는다. 폴백 카드는 예고 없이 그냥 카드로 나간다 — 사용자 화면에서 정상 카드와 구별되지 않아야 한다.

### 폴백 카드

**파일을 하나도 열지 않고 만든다.** 형식과 내용이 이 절 안에 전부 있다 — 참조 파일도 함께 실패했을 수 있으므로 여기서 나가지 않는다.

**표를 보기 전에 캘린더부터 확인한다.** 위 [캘린더](#캘린더)의 두 호출을 그대로 밟아 다음 busy를 받고, 다음 일정이 있으면 `이유`를 "다음 일정까지 N분"으로 쓴다. **커넥터는 파일이 아니라 도구이므로 설치가 깨져도 살아 있다** — 스크립트가 죽은 상황에서 캘린더가 붙는 유일한 경로다. 한 번에 안 되면 시각만 쓰고 넘어간다.

**네 줄의 순서는 고정이다.** 아래 표에서 값을 뽑아 이 순서로 낸다.

```
- **지금** → (표의 지금)
- **이유** → (현재 시각), (표의 이유)
- **시작** → (표의 시작)
- **종료** → (표의 종료)
```

| 시각 | 지금 | 이유 | 시작 | 종료 |
|---|---|---|---|---|
| ~11시 | 하루 시작 | 첫 30분이 오늘 흐름을 정함 | 어제 마지막으로 열었던 파일 열기 | 화면에 떠 있으면 |
| 11~13시 | 끊긴 데로 복귀 | 오전에 보던 것부터 | 아까 보던 창 하나 열기 | 그 창이 앞에 오면 |
| 13~14시 | 자리 잡기 | 점심 뒤 첫 동작 | 책상 위 하나 치우기 | 그거 하나 치우면 |
| 14~16시 | 하나만 집기 | 퇴근까지 아직 남음 | 지금 열려 있는 문서에 한 줄 쓰기 | 한 줄이 들어가면 |
| 16시~ | 하루 닫기 | 지금 적어두면 내일 안 헤맴 | 지금 열린 창이나 파일 하나 열기 | 그 창을 닫으면 |

**행을 시각으로 정확히 고른다.** 15시 26분은 `14~16시` 행이지 `16시~` 행이 아니다.

잔여 상태 줄은 `미처리 0 · 오늘 마감 0`으로 낸다. 선택지는 `완료` / `다른 거` / `오늘 그만` 셋만 낸다 — 이미 최소 크기라 `너무 큼`은 뺀다.

**기록은 포기한다.** 토큰이 없으므로 `완료`를 눌러도 `complete`를 부르지 않는다. 다시 실패할 뿐이다. 수확 두 칸만 받아 화면에 남기고 같은 방식으로 다음 카드를 낸다.

사용자는 3초 안에 카드를 받아야 한다. **조용한 3분은 틀린 카드보다 훨씬 나쁘다.** 상태가 한 세션 날아가는 것은 감수할 수 있는 손실이고, 사용자가 빈 화면 앞에서 진단 로그를 보는 것은 감수할 수 없는 손실이다.

## 쓰지 않는 경우

트리거된 뒤에 판단한다. 다음은 대상이 아니므로 평소대로 답한다.

- 할 일 목록 전체를 보여 달라고 명시적으로 요청한 경우
- 계획 수립, 일정 조율, 우선순위 체계 설계 요청
- 특정 업무를 어떻게 하는지 물어보는 경우

응답이 길어졌다면 거의 항상 절대 규칙 중 하나를 어긴 것이다.
