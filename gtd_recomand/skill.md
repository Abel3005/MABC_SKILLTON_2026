# GTD Now-Recommend 스킬

## 개요

사용자가 "지금 뭐 해야 하지?"라고 물었을 때, GTD 원칙에 따라
보유 중인 일정/할 일 데이터를 분석해 최적의 다음 행동을 추천한다.

GTD의 핵심 질문 프레임워크:
1. ** 지금 내 컨텍스트는?** — 장소, 도구, 사람, 상태 (예: `@집`, `@컴퓨터`, `@전화`)
2. **지금 얼마나 시간이 있나?** — 5분, 15분, 30분, 1시간, 2시간+
3. **내 에너지/집중도는?** — 높음, 보통, 낮음
4. **마감/시한은?** — 오늘 마감, 이번 주, 여유 있음
5. **가장 중요한 것은?** — 다음 행동 중 영향도/결과감이 가장 큰 것

## 추천 알고리즘 (단계별)

### Step 1 — 입력 데이터 정규화

입력으로 받을 수 있는 데이터:
- **캘린더 일정**: 시간대 + 제목 + 장소/링크 (Google Calendar, 수기 등)
- **할 일/Next Actions 목록**: 각 항목에 컨텍스트 태그(`@컴퓨터`, `@집` 등), 예상 소요 시간, 마감일, 우선순위
- **프로젝트 목록**: 진행 중인 프로젝트와 그 하위 Next Action
- **Waiting For / Someday 리스트**: 이번엔 제외, 참고용만

각 액션을 아래 스키마로 정규화한다:

```
{
  id:            "uniq-id",
  title:         "액션 제목",
  type:          "action" | "calendar_event" | "time_block",
  context_tags:  ["@컴퓨터", "@전화"],          // 빈 배열이면 모든 컨텍스트에서 가능
  estimated_min: 15,                             // 예상 소요 시간 (분)
  deadline:      "2026-08-20T18:00:00+09:00",  // 마감 일시 (없으면 null)
  priority:      1|2|3|4|5,                     // 1=높음, 5=낮음 (없을 경우 3)
  energy:        "high" | "normal" | "low",    // 예상 필요 에너지
  project:       "프로젝트명",                   // 소속 프로젝트
  deferred:      false,                          // 연기 여부
  notes:         "...",                          // 참고 메모
}
```

### Step 2 — 현재 상황 파악

- **현재 시각** `now`
- **캘린더에서 다음 일정까지 남은 시간** `gap_to_next` = 다음 일정 시작 시각 - now
- **당장 비어있는 블록의 길이** `available_window` = min(gap_to_next, 사용자가 설정한 최대 집중 단위, 예 90분)
- **현재 컨텍스트** \(C_{now}\): 사용자가 현재 있는 장소/접속 가능한 도구 (대화에서 파악하거나 기본값 사용)
- **현재 에너지** \(E_{now}\): 사용자가 말한 상태, 또는 기본값 "normal"

### Step 3 — 필터링 (실행 가능 액션만 남기기)

각 액션 \(a\) 에 대해:

1. **컨텍스트 필터**: `context_tags`가 비어 있거나 \(C_{now} \in context\_tags\) → 통과
2. **시간 필터**: `estimated_min <= available_window * 0.9` → 통과 (버퍼 포함)
3. **에너지 필터**: `energy`가 \(E_{now}\)와 심하게 불일치하면 후순위로 (예: 고에너지 작업을 낮은 에너지로 하려 할 때)
4. **마감 임박 필터**: 이미 지난 마감일은 "긴급" 플래그, 1시간 이내 마감은 "준긴급"

### Step 4 — 우선순위 점수 계산

실행 가능 후보 각각 점수 \(S\) :

\[
S = w_d \cdot D + w_p \cdot P + w_e \cdot E + w_t \cdot T + w_c \cdot C
\]

| 요소 | 계산 | 방향 |
|---|---|---|
| \(D\) 마감 시급성 | 1시간 이내=1.0, 오늘=0.8, 이번 주=0.5, 여유=0.2 | 높을수록 좋음 |
| \(P\) 우선순위 | \(6 - priority\) (1→5, 5→1) | 높을수록 좋음 |
| \(E\) 에너지 적합도 | 잘 맞으면 1.0, 조금 어긋나면 0.5, 크게 어긋나면 0.1 | 높을수록 좋음 |
| \(T\) 시간 적합성 | estimated_min이 available_window에 잘 맞으면 1.0, 너무 작으면 0.7, 넘치면 0.0(이미 필터됨) | 높을수록 좋음 |
| \(C\) 컨텍스트 일치 | 정확히 일치=1.0, 태그 없음(어디서나)=0.9 | 높을수록 좋음 |

기본 가중치:
```
w_d=0.35, w_p=0.25, w_e=0.15, w_t=0.15, w_c=0.10
```
사용자가 "마감이 급해", "에너지가 없어" 등의 단서를 주면 가중치를 실시간 조정.

### Step 5 — 추천 구성

상위 1~3개 액션을 아래 형식으로 추천한다:

```
## 지금 추천하는 다음 행동

**1순위: [액션 제목]**
- 이유: [마감/우선순위/컨텍스트 기반 한 줄 설명]
- 예상 시간: N분
- 컨텍스트: [@태그]  |  에너지: 높음/보통/낮음
- 팁: [바로 시작하는 구체적 첫 동작 한 가지]

**2순위: [액션 제목]** (1순위가 안 되면)
- ...

**시간이 X분밖에 없다면:** [5분 내 끝나는 마이크로 액션]
```

### Step 6 — 대안 제안 (선택)

- **시간이 생각보다 짧다면**: 5분 내 끝나는 액션, 또는 다음 액션의 준비 작업
- **에너지가 낮다면**: 이메일 정리, 파일 정리, 간단한 검토 등 낮은 에너지 작업
- **에너지가 높다면**: 창의적 작업, 어려운 문제 해결, 깊은 집중이 필요한 작업
- **컨텍스트가 바뀌었다면**: 새 컨텍스트에 맞는 액션 재추천

### 사용자 입력 예시

### 스킬의 응답 예시

```
현재 시각 오후 1시 40분, 다음 캘린더 일정(오후 2시 팀 미팅)까지 20분 남았네요.

**지금 추천하는 다음 행동**

**1순위: 클라이언트 보고서 데이터 정리**
- 이유: 오늘 마감이면서 @컴퓨터 컨텍스트와 딱 맞고 15분 안에 마무리 가능한 작업
- 예상 시간: 15분
- 컨텍스트: @컴퓨터  |  에너지: 보통
- 팁: 스프레드시트에서 '2026-08' 시트만 먼저 열어보세요

**시간이 5분밖에 없다면: 읽지 않은 이메일 3개 처리 (0분 대기)**
- 이유: @컴퓨터, 낮은 에너지, 5분 내 완료 가능
```

## 입력 데이터 예시 (사용자가 제공할 수 있는 형태)

### 캘린더 일정 (예시)

```
오후 1:00-1:30 이메일 정리 (완료)
오후 2:00-2:30 팀 스탠드업 미팅
오후 4:00-5:00 클라이언트 1:1 미팅
오후 6:00 치과 예약
```

### 할 일 / Next Actions (예시)

```
- [ ] @컴퓨터 클라이언트 보고서 데이터 정리 (마감: 오늘 18시, 우선순위: 높음, 15분)
- [ ] @전화 공급사에 납기 확인 전화 (마감: 오늘 15시, 10분)
- [ ] @집 세탁기 돌리기 (소소한 일, 5분)
- [ ] @컴퓨터 Q3 기획안 초안 쓰기 (마감: 이번 주 금요일, 90분, 높은 에너지)
- [ ] @컴퓨터 주차별 실적 업데이트하기 (마감: 오늘 12시 이미 지남, 20분)
- [ ] @사무실 택배 수령 (컨텍스트: @사무실, 5분)
- [ ] @컴퓨터 디자인 시안 리뷰 (마감: 내일, 40분, 보통 에너지)
- [ ] 프로젝트 '웹사이트 리뉴얼' — 이번 주 목요일까지 디자인 확정
```

## 활용 팁 / GTD 원칙 노트

1. **Next Action 중심**: 프로젝트는 추천하지 않는다 — 실행 가능한 구체적 다음 행동만 추천한다.
2. **2분 규칙**: 2분 안에 끝나는 일은 추천 목록에서 "당장 해" 플래그로 강조한다.
3. **컨텍스트 유지**: 비슷한 컨텍스트의 액션이 여러 개면 묶어서 추천하고, 컨텍스트 전환 비용을 언급한다.
4. **붕괴(blocking) 관계**: A 작업을 끝내야 B를 시작할 수 있다면, A를 먼저 추천하도록 의존성을 반영한다(데이터에 dependency 필드가 있을 경우).
5. **에너지 데이터**: 사용자가 평소에 "아침엔 집중 잘 됨", "점심 후엔 처짐" 같은 패턴을 제공하면 시간대-에너지 매핑을 학습해 점수 계산 보정.
6. **캘린더 간격 활용**: 캘린더 사이의 빈 시간(gap)을 자동으로 찾고, 그 길이에 맞는 액션을 추천 — "다음 일정까지 20분"을 강조.
7. **오늘의 "반드시 오늘" 마감**: 오늘 마감인 일이 없으면 "오늘 반드시 끝내야 할 일은 없네요 — 하고 싶은/미뤄둔 일을 고르세요" 라고 안내.

## 확장 — 데이터 소스 연동

이 스킬은 입력 데이터를 **텍스트로 받아서 처리**하는 것이 기본이다.
별도 데이터 소스(구글 캘린더, 태스크 앱 등) 연동이 필요하면 해당 MCP/커넥터를
추가 설치하고, 이 스킬이 데이터를 가져오는 단계를 추가하면 된다.

현재는 연결 가능한 데이터 소스를 확인하려면 아래처럼 찾는다:

```bash
# 캘린더 연동 가능한 MCP/앱 찾기
find_tool("google calendar")
find_tool("calendar")
find_tool("task / 할일")
```

## 스킬 호출 방법

사용자가 "지금 뭐 해야 해?", "다음 행동 추천해줘", "2시 미팅 전까지 뭐 할까?"
처럼 말하면 이 스킬을 활성화해 대화형 추천을 진행한다.

더 정교한 추천을 위해서는 사용자로부터 아래 정보를 받으면 좋다:

1. **현재 컨텍스트**: 지금 어디/어떤 도구로 작업 가능한지
2. **현재 에너지**: 높음/보통/낮음
3. **시간 제약**: 다음 일정, 또는 "지금 N분만 가능"
4. **할 일/캘린더 데이터**: 텍스트, 붙여넣기, 또는 연동된 앱의 데이터
